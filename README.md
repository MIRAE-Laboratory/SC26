# SC26 온톨로지

SC26 세션의 초록을 읽고 발표·문제·기법·대상 시스템의 관계를 그래프로 정리한 저장소입니다.
데이터는 `data/`의 YAML이고, `index.html`이 이를 브라우저에서 직접 읽어 대화형 그래프로 보여 줍니다.

## 구조

| 경로 | 내용 |
|---|---|
| `index.html` | 뷰어. 브라우저에서 YAML을 직접 읽어 검증하고 그래프로 그립니다 (빌드 단계 없음). |
| `schema.yaml` | 클래스 7종과 관계 8종 정의. 위반 사항은 뷰어 상단에 경고로 표시됩니다. |
| `data/manifest.yaml` | 뷰어가 읽을 세션·발표 파일 목록 |
| `data/sessions/`, `data/presentations/` | 세션·발표당 파일 하나 (요약과 핵심 주장 포함) |
| `data/concepts.yaml` | 세션 간에 공유되는 Problem / Method / System 개념 |
| `data/people.yaml`, `data/orgs.yaml` | 인물과 소속 기관 |
| `media/`, `transcripts/` | 현장 사진과 발표 녹취록 (세션별 하위 폴더) |
| `vendor/` | Cytoscape.js, js-yaml (외부 CDN 없이 동작) |

## 사용법

GitHub에 올린 뒤 Settings → Pages → Source를 **Deploy from a branch**, `main` / `/ (root)`로 지정하면 끝입니다. YAML을 수정해 push하면 페이지에 바로 반영됩니다.

로컬에서는 파일을 직접 열면 브라우저가 YAML 읽기를 막으므로 간단한 서버로 엽니다.

```bash
python -m http.server 8000   # http://localhost:8000
```

세션을 추가하려면 `data/sessions/`와 `data/presentations/`에 파일을 넣고 `data/manifest.yaml`에 경로를 적습니다. 새 개념만 `data/concepts.yaml`에 더하고, 기존 개념 id를 재사용할수록 세션 간 연결이 드러납니다.

## 현장 자료 (사진·녹취록)

발표 YAML에 아래 필드를 더하면 뷰어 상세 패널에 표시됩니다. 모두 선택 사항입니다.

```yaml
photos:
  - {file: media/sess126/ws_shpc101-01.jpg, caption: 공격 트리 슬라이드}
transcript: transcripts/sess126/ws_shpc101.md
claims:
  - 문자열만 쓰면 출처 표시 없이 나옵니다.
  - {text: 발표에서만 언급된 내용, source: talk, at: "07:42"}   # source: abstract | talk | slide | qa
```

## 수록 세션

- `sess126` — S-HPC 2026: 5th International Workshop on Cyber Security in HPC (2026-11-15)
- `sess114` — AI4S: 8th Workshop on Artificial Intelligence and Machine Learning for Scientific Applications (2026-11-15)

요약과 주장은 공개 프로그램 페이지의 초록을 한국어로 요약한 것이며 원문 인용이 아닙니다. 패널(`miscp115`)과 초청 강연 두 건(`misc226`, `misc217`)은 공개된 설명문이 없어 제목과 참여자만 담았습니다.

## 고찰 (sess126)

1. **위협 주체가 내부로 이동했습니다.** 특권 운영자, 공동 테넌트, 일탈 연구자(101), 참여 기관(102), 자율 에이전트(초청 강연)가 적대자 모델의 중심입니다. "인증된 사용자만 들인다"는 기존 HPC 보안 전제가 멀티테넌트 AI 환경에서는 성립하지 않습니다.
2. **운영 데이터가 누출 경로이자 탐지 재료입니다.** 스케줄러 메타데이터(102)와 전력 텔레메트리(106)는 워크로드와 기관 전략을 드러내고, 같은 종류의 텔레메트리가 공격 탐지(105)의 입력입니다. 텔레메트리를 얼마나 세밀하게 공개할지는 프라이버시와 관측성 사이의 절충이며, 106은 샘플링 완화만으로는 부족하다고 결론짓습니다.
3. **AI는 공격과 방어 양쪽에 있습니다.** 코딩 에이전트가 재현 가능한 익스플로잇 59개를 만들었고(104), 반대편에서는 에이전트의 행동 경계를 런타임에서 강제하는 방법이 논의됩니다(초청 강연).
4. **과학 코드 자체가 공격 표면입니다.** 네 개 응용에서 약 1,000건의 크래시가 나왔다는 104의 결과는, 비신뢰 입력을 받는 워크플로에서 계산 결과의 무결성을 따로 보증해야 함을 뜻합니다.
5. **책임과 주장을 명시하는 틀이 공통 해법입니다.** 101은 공격 경로마다 책임 주체를 대응시키고, 102는 프라이버시 주장을 감사 가능한 양식으로 만들며, 패널은 표준과 컴플라이언스를 다룹니다. 기술 통제보다 "누가 무엇을 보증하는가"의 정식화가 세션 전체의 흐름입니다.
6. **암호화 연산은 아직 규모가 작습니다.** 동형암호 그래프 연산(107)은 1,024 랭크를 쓰고도 N=16에서 5.66배 가속 수준이어서, 실용 규모와의 거리가 큽니다.

## 고찰 (sess114)

1. **에이전트가 과학 워크플로의 조율자가 되었습니다.** 실행 환경 구성(EnvAgent), 빔라인 스펙트럼 분석(LightshowAI-Agent), 생성 코드 평가(PETScAgent-Bench)가 모두 에이전트 구조이고, 논문 발표 12건 중 4건이 에이전트를 다룹니다.
2. **에이전트는 HPC 인프라의 전제를 깹니다.** 계층형 스토리지는 접근 패턴이 예측 가능하다는 가정 위에 서 있는데, 에이전트가 다음 작업을 정하면 실행 시간이 3.18배 늘었습니다(128). 인프라가 에이전트의 신호를 읽도록 다시 설계되어야 한다는 주장입니다.
3. **대리모델의 이득은 모델보다 배치와 이산화에서 나옵니다.** Coconut은 같은 대리모델이 배치 구성에 따라 2.4배 느려지기도, 34배 빨라지기도 함을 보였고, 격자 볼츠만 GNN은 8.9배 가속이 전부 격자 조대화에서 나온다고 제목에서 밝힙니다.
4. **물리 신호를 넣는 것이 안정성의 열쇠입니다.** 압력 탭 12개의 측정값만으로 롤아웃 오차를 48%에서 6%대로 낮추고(ETCH), 증강 라그랑지안 학습은 제약 위반을 약 19배 줄입니다(ACOPF).
5. **한계를 그대로 보고하는 발표가 많습니다.** 역설계는 출력에 정보가 남지 않아 한계가 있다는 부정적 결과(106), 최신 모델이 라이브러리 관례에서 약하다는 평가(109), 최고 정확도는 여전히 과제별 모델이라는 결론(127)이 그렇습니다. 통과/실패나 단일 가속 수치로는 부족하다는 인식이 공통입니다.

## 세션 간 연결 (sess126 ↔ sess114)

- 두 세션을 잇는 개념은 **AI 에이전트**입니다. 보안 워크숍에서는 경계를 강제해야 할 대상이고(초청 강연), AI4S에서는 생산성 도구입니다. 그래프에서 두 세션 사이 기둥에 놓입니다.
- AI4S의 MCP 타입 지정 도구, 버전 관리되는 스킬 파일, MLflow·Tiled 기록(131)은 보안 워크숍이 요구한 "에이전트 행동의 강제 가능한 경계와 감사 가능성"을 구현하는 재료로 읽을 수 있습니다. 이는 두 초록을 나란히 놓고 내린 해석이며 어느 발표도 직접 말한 내용은 아닙니다.
- 코딩 에이전트는 한쪽에서 익스플로잇 59개를 만들고(126의 104), 다른 쪽에서는 관례를 어긴 과학 코드를 만듭니다(114의 109). 둘 다 "컴파일되고 실행된다"가 품질 기준이 될 수 없음을 보여 줍니다.
- 인물로는 Kibaek Kim(ANL)이 양쪽 세션에 저자로 있고, 기관으로는 ANL, ORNL, NVIDIA, INRIA, UIC가 겹칩니다.
